These guides explain; Swagger specifies. The spec is generated from code, so
it is always current. This page covers where to find it, how it is produced,
and how the SDKs stay in sync with it.

## Where it lives

| Artifact | Location | Notes |
|---|---|---|
| Swagger UI | `http://localhost:8080/swagger/index.html` | Interactive "try it out", served by the API |
| Raw spec (Swagger 2.0) | `rallya/docs/swagger.json` | Generated by `swag`, committed |
| Raw spec (YAML) | `rallya/docs/swagger.yaml` | Same content, YAML form |
| OpenAPI 3.0 conversion | `rallya-js-sdk/openapi3.json` | Produced by `swagger2openapi` |
| OpenAPI snapshot | `rallya-js-sdk/openapi.snapshot.json` | Byte-copy of `swagger.json` used for drift detection |
| Generated TS types | `rallya-js-sdk/src/generated/schema.ts` | Produced by `openapi-typescript` (~7,800 lines) |

Serving is via `gin-swagger` on the `/swagger/*any` route group. Two routes are
absent from the spec: `GET /health` (outside `/api/v1`) and `GET /api/v1/hello`
(no annotations) — both are unauthenticated.

## What's in the spec

- **74 paths**, all under base path `/api/v1` (host `localhost:8080` in dev),
  plus the Stripe webhook at `/webhooks/stripe`.
- **99 definitions** — every DTO, grouped per domain (`authdto`-style:
  `dto`, `orgdto`, `eventdto`, `ticketdto`, `orderdto`, `attendeedto`,
  `checkindto`, `kitdto`, `subdto`, `auditdto`, `admindto`, payment/misc
  `ErrorAlias`es). Full field-level reference: [Schemas](/docs/schemas).
- **Security**: `BearerAuth` (JWT bearer) on every protected route. The
  `X-API-Key` server-to-server mode is **not** declared in the spec — API-key
  callers use the same routes with the `X-API-Key` header (see
  [API Keys](/docs/api-keys)); the spec only documents bearer auth.
- **Pagination**: every `*Page` definition carries `items`, `total`, `page`,
  `perPage` (server defaults 1/20, max 100). SDKs backfill `page`/`perPage`
  from the request when a route omits them.
- **Stealth 404s**: outsiders get indistinguishable 404s for orgs, events,
  and others' orders — the spec cannot express "not found or no access".
- **Error envelope**: `{error}` everywhere, plus `{error, code}` on billing
  (`UPGRADE_REQUIRED`, `BILLING_UNAVAILABLE`, `ALREADY_SUBSCRIBED`,
  `INVALID_PLAN`) and auth (`EMAIL_NOT_VERIFIED`) routes. Gateway for the
  full shape: [API Conventions](/docs/api-conventions).

## How it is generated (backend)

Annotations on handlers are the source of truth. Never hand-edit
`rallya/docs/swagger.json` — regenerate it:

```bash
swag init -g cmd/api/main.go -o docs   # from the rallya repo root
```

Rules that keep generation clean:

- Swagger annotations on **every** route (summary, params, responses,
  security). A route without annotations is invisible in the UI.
- DTOs live in `internal/<domain>/dto/` with **unique package names per
  domain** — `swag` fails on duplicate definition names.
- Regenerate after **any** behavior change (paths, params, responses,
  envelope). The committed spec must match the code at merge time.
- `coder`-style aliases (`ErrorAlias`, `MessageAlias`) exist because Go type
  aliases would collide across packages.

## How the SDKs consume it

### TypeScript (`@rallya/sdk`)

```bash
npm run gen         # swagger.json → openapi3.json → src/generated/schema.ts
npm run gen:check   # fail CI if the committed spec drifted
```

`gen` runs `swagger2openapi` then `openapi-typescript`, and copies
`swagger.json` → `openapi.snapshot.json`. `gen:check` hashes
`../rallya/docs/swagger.json` and the snapshot — if the backend changed
without re-running `npm run gen`, CI fails. Determinism is double-checked by
re-converting the snapshot to OpenAPI 3 with `swagger2openapi` and requiring
it to succeed.

Practical flow when the API changes:

1. Backend merges annotated changes + regenerated `docs/swagger.json`.
2. SDK repo runs `npm run gen`, reviews the `schema.ts` diff, hand-adjusts
   `src/types.ts` (the ergonomic 1:1 mirror), adds types/tests, bumps version.
3. `npm run gen:check` passes again before release.

### Go (`rallya-go-sdk`)

The Go SDK is a hand-maintained port of `@rallya/sdk` — no code generation.
Types in `types.go` mirror the DTOs by hand; keep them in step with the
spec when it changes.

## Using Swagger UI

1. Run the API locally (`go run ./cmd/api` or compose).
2. Open `http://localhost:8080/swagger/index.html`.
3. Click **Authorize**, paste an access token as `Bearer <token>` (or leave
   it — public routes need no auth).
4. Try endpoints. Non-2xx responses follow the `{error}` envelope; see
   [API Conventions](/docs/api-conventions) for status-code semantics
   (402/403/404/409/413/422/429).

The UI is a debugging and discovery tool, not a contract test suite —
envelopes typed in code are enforced only by tests and SDK types.

## Which one do I read?

| You want | Go to |
|---|---|
| Exact params, required fields, all response codes | Swagger UI / `swagger.json` |
| Field-by-field schema listing (this repo's reference) | [Schemas](/docs/schemas) |
| Typed client usage, ergonomics, retry semantics | [TypeScript SDK](/docs/sdk-typescript), [Go SDK](/docs/sdk-go) |
| Auth modes, keys, rotation | [API Keys](/docs/api-keys), [Auth](/docs/auth) |
| Route tables with gate notes | [Endpoints](/docs/endpoints) |

When they disagree, the **generated spec wins** (it is produced from the
code), then SDK types, then these guides — file a docs fix.
